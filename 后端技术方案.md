# 「边界舱」后端及数据库技术方案

## 一、技术栈选型

### 后端框架
- **推荐方案**：Node.js + Express.js / Python + FastAPI / Go + Gin
- **推荐理由**：
  - Node.js：JavaScript 全栈，开发效率高，生态丰富
  - Python + FastAPI：开发快速，类型安全，文档自动生成
  - Go + Gin：性能优秀，并发处理能力强，适合高并发场景

### 数据库
- **主数据库**：PostgreSQL 14+
  - 关系型数据（用户、关系、邀请、确认等）
  - JSONB 支持（灵活存储复杂结构）
  - 全文搜索支持
  - 时间序列数据优化

- **缓存层**：Redis 7+
  - 用户会话管理
  - 实时状态缓存（能量状态、在线状态）
  - 热点数据缓存
  - 分布式锁

- **文件存储**：AWS S3 / 阿里云 OSS / 腾讯云 COS
  - 图片存储（碎片、瞬间）
  - CDN 加速

### 实时通信
- **WebSocket**：用于实时状态同步
- **推送服务**：APNs (Apple Push Notification Service)

### 认证授权
- **JWT (JSON Web Token)**：无状态认证
- **OAuth 2.0**：第三方登录（可选）

## 二、数据库设计

### 2.1 核心表结构

#### 用户表 (users)
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    phone VARCHAR(20) UNIQUE NOT NULL,  -- 手机号（登录账号）
    nickname VARCHAR(50),                -- 昵称
    avatar_url TEXT,                    -- 头像URL
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    last_seen_at TIMESTAMP,             -- 最后活跃时间
    is_active BOOLEAN DEFAULT TRUE,
    
    -- 能量状态相关（实时状态，缓存到Redis）
    current_energy_level VARCHAR(10) DEFAULT 'unplanned',  -- 🟢/🟡/🔴/⚪
    focus_mode_enabled BOOLEAN DEFAULT FALSE,
    
    INDEX idx_phone (phone),
    INDEX idx_created_at (created_at)
);
```

#### 关系表 (relationships)
```sql
CREATE TABLE relationships (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user1_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    user2_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    status VARCHAR(20) NOT NULL,  -- pending/active/blocked/ended
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    invited_by UUID REFERENCES users(id),
    
    UNIQUE(user1_id, user2_id),
    CHECK(user1_id < user2_id),  -- 确保关系唯一性
    INDEX idx_user1 (user1_id),
    INDEX idx_user2 (user2_id),
    INDEX idx_status (status)
);
```

#### 能量状态记录表 (energy_records)
```sql
CREATE TABLE energy_records (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    record_date DATE NOT NULL,           -- 记录日期
    record_type VARCHAR(20) NOT NULL,    -- base/planned/temporary
    energy_level VARCHAR(10) NOT NULL,   -- 🟢/🟡/🔴/⚪
    
    -- 时间段信息（JSONB存储）
    time_slots JSONB NOT NULL,           -- [{startHour, startMinute, endHour, endMinute}]
    
    -- 临时状态特有字段
    temporary_type VARCHAR(20),           -- fastCharge/lowPower
    original_energy_level VARCHAR(10),   -- 临时状态前的原始状态
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    
    UNIQUE(user_id, record_date, record_type),
    INDEX idx_user_date (user_id, record_date),
    INDEX idx_record_type (record_type)
);
```

#### 能量状态变更历史表 (energy_level_changes)
```sql
CREATE TABLE energy_level_changes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    change_time TIMESTAMP NOT NULL,
    new_energy_level VARCHAR(10) NOT NULL,
    change_type VARCHAR(20),             -- manual/temporary/planned
    
    INDEX idx_user_time (user_id, change_time)
);
```

#### 协作邀请表 (collaboration_invitations)
```sql
CREATE TABLE collaboration_invitations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    created_by UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    target_user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    start_time TIMESTAMP,
    location VARCHAR(200),
    status VARCHAR(20) DEFAULT 'pending',  -- pending/accepted/rejected/cancelled
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    responded_at TIMESTAMP,
    
    INDEX idx_created_by (created_by),
    INDEX idx_target_user (target_user_id),
    INDEX idx_status (status),
    INDEX idx_start_time (start_time)
);
```

#### 安心确认表 (peaceful_closures)
```sql
CREATE TABLE peaceful_closures (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    created_by UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    target_user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    closure_type VARCHAR(20) NOT NULL,   -- item/affair
    
    title VARCHAR(200) NOT NULL,
    content TEXT,
    
    -- 物品类特有字段（JSONB）
    item_details JSONB,                  -- {itemName, location, expectedTime, extraInfo}
    
    status VARCHAR(20) DEFAULT 'pending', -- pending/completed/archived/expired/cancelled
    response JSONB,                       -- {content, timestamp, isFinal}
    
    expires_at TIMESTAMP,
    has_expiration BOOLEAN DEFAULT FALSE,
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    responded_at TIMESTAMP,
    
    INDEX idx_created_by (created_by),
    INDEX idx_target_user (target_user_id),
    INDEX idx_status (status),
    INDEX idx_expires_at (expires_at)
);
```

#### 心意盒表 (gift_boxes)
```sql
CREATE TABLE gift_boxes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    created_by UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    target_user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    
    item VARCHAR(200) NOT NULL,
    note TEXT,
    suggested_location VARCHAR(200) NOT NULL,
    preparation_time INTEGER NOT NULL,   -- 准备时间（分钟）
    
    status VARCHAR(20) DEFAULT 'pending', -- pending/accepted/rejected/expired/withdrawn
    
    -- 接收方填写的信息（JSONB）
    accepted_info JSONB,                 -- {startTime, endTime, actualLocation}
    response VARCHAR(50),                 -- accepted/rejected
    responded_at TIMESTAMP,
    
    has_expiration BOOLEAN DEFAULT FALSE,
    expires_at TIMESTAMP,
    
    is_withdrawn BOOLEAN DEFAULT FALSE,
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    last_edited_at TIMESTAMP,
    
    INDEX idx_created_by (created_by),
    INDEX idx_target_user (target_user_id),
    INDEX idx_status (status),
    INDEX idx_expires_at (expires_at)
);
```

#### 碎片表 (fragments)

```sql
    is_read BOOLEAN DEFAULT FALSE,
    is_withdrawn BOOLEAN DEFAULT FALSE,
    
    created_at TIMESTAMP DEFAULT NOW(),
    read_at TIMESTAMP,
    
    INDEX idx_created_by (created_by),
    INDEX idx_target_user (target_user_id),
    INDEX idx_is_read (is_read),
    INDEX idx_created_at (created_at)

```

#### 瞬间表 (moments)
```sql
CREATE TABLE moments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    created_by UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    
    content TEXT NOT NULL,
    images TEXT[],                        -- 图片URL数组
    is_text_hidden BOOLEAN DEFAULT TRUE,  -- 文案是否隐藏（3天规则）
    
    likes INTEGER DEFAULT 0,
    comments INTEGER DEFAULT 0,
    
    created_at TIMESTAMP DEFAULT NOW(),
    
    INDEX idx_created_by (created_by),
    INDEX idx_created_at (created_at)
);
```

#### 通知表 (notifications)
```sql
CREATE TABLE notifications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    
    category VARCHAR(20) NOT NULL,        -- info/reminder
    type VARCHAR(50) NOT NULL,            -- invitation_accepted/gift_box_received等
    title VARCHAR(200) NOT NULL,
    content TEXT,
    
    is_read BOOLEAN DEFAULT FALSE,
    end_time TIMESTAMP,                   -- 提醒类通知的结束时间
    
    created_at TIMESTAMP DEFAULT NOW(),
    read_at TIMESTAMP,
    
    INDEX idx_user_id (user_id),
    INDEX idx_is_read (is_read),
    INDEX idx_category (category),
    INDEX idx_created_at (created_at)
);
```

#### 心情记录表 (mood_records)
```sql
CREATE TABLE mood_records (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    
    value DOUBLE PRECISION NOT NULL,     -- 心情值（0-10）
    note TEXT,
    
    recorded_at TIMESTAMP DEFAULT NOW(),
    
    INDEX idx_user_id (user_id),
    INDEX idx_recorded_at (recorded_at)

```

#### Maybe清单表 (maybe_items)
```sql
CREATE TABLE maybe_items (

```

#### 成长花园表 (growth_garden)

#### 物品类型表 (item_types)
```sql

    icon VARCHAR(50),

    is_default BOOLEAN DEFAULT FALSE,
```

## 七、安全方案

### 7.1 认证安全
- JWT Token 有效期：7天
- Refresh Token 有效期：30天
- Token 存储在 HTTP-only Cookie 或安全存储中
- 支持 Token 撤销机制

### 7.2 数据安全
- 所有敏感数据加密存储
- API 接口使用 HTTPS
- SQL 注入防护（使用参数化查询）
- XSS 防护（输入验证和输出转义）

### 7.3 权限控制
- 用户只能访问自己的数据和关系内的数据
- 关系验证：所有涉及伴侣的操作都需要验证关系状态
- 操作日志记录：记录关键操作（创建、修改、删除）

## 十、技术难点与解决方案

### 10.1 能量状态的分钟级精度
**问题**：需要精确到分钟的能量状态记录和查询

**解决方案**：
- 使用 JSONB 存储时间段数组
- 建立时间索引优化查询
- 使用 Redis 缓存当前状态

### 10.2 实时状态同步
**问题**：多设备登录时的状态同步

**解决方案**：
- WebSocket 连接管理
- 状态变更时广播给所有连接的设备
- 使用 Redis Pub/Sub 实现消息分发

### 10.3 关系数据的隐私保护
**问题**：确保用户只能访问关系内的数据

**解决方案**：
- 所有查询都加入关系验证
- 使用数据库行级安全策略（RLS）
- API 层进行权限校验

### 10.4 高并发场景
**问题**：大量用户同时更新状态

**解决方案**：
- 使用 Redis 分布式锁
- 数据库连接池优化
- 异步任务队列处理非实时操作
